# Credits — Temple Rush: Curse of the Lost Kingdom

An original game inspired by the endless-runner genre. No proprietary code,
trademarks, characters or assets from *Temple Run* (Imangi Studios) or any
other commercial game are used or redistributed. The title, art direction,
code and audio in this repository are original works.

## Development

* **Engine, gameplay, UI, tools** — written from scratch in this repository
  (three.js WebGL rendering, ES modules, HTML/CSS UI).
* **Art direction** — gold-on-jungle palette; all textures, sprites and UI
  art generated by the repo's own asset pipeline (`tools/process_assets.py`)
  from source plates kept in `assets/raw/`.
* **Audio** — 100 % synthesized at runtime with the Web Audio API
  (`js/core/audio.js`): SFX, generative soundtrack and jungle ambience.
  No sampled audio files ship with the game.

## Asset provenance & acquisition policy

The build environment allowed network access only to package registries
(npm / PyPI) and GitHub, so third-party asset libraries (Kenney, Poly Haven,
Quaternius, OpenGameArt, ambientCG, Freesound, Mixamo, Sketchfab) could
**not** be downloaded and were not used. Per the project brief, the
sanctioned alternative was applied instead: **every asset was created in this
repository** —

* textures, sprites, character frames and UI art: generated / processed by
  `tools/process_assets.py` (chroma-keying, slicing, procedural coin, sky
  panorama conversion),
* 3D geometry for obstacles, coins, idols, enemies and scenery: built
  procedurally in three.js (`js/game/entities.js`, `js/render/environment.js`)
  — Blender and GLTF binaries were unavailable and are not required,
* music, ambience and every sound effect: synthesized with Web Audio
  oscillators, noise buffers and filters at runtime.

Consequently there are **zero external runtime dependencies and zero broken
links**: the game never fetches anything outside its own folder.

## QA — what was actually tested

Verified in the build environment (Node 22 + three.js, no GPU browser):

* `npm run test:wiring` — every DOM id referenced by JS exists in
  `index.html`; every asset path referenced by JS/HTML/CSS exists on disk;
  every relative and bare import resolves (import map checked).
* `npm run test:scene` — the full scene graph (environment, entities, player,
  particles) builds under Node; a full run is played with an autopilot:
  lane switching, jumping, sliding, collisions, coins, power-ups (incl. the
  Score ×2 multiplier), stumble, death, revive and dispose are exercised.
* `npm run test:play` — 6+ autopilot runs of up to 200 s each through all
  three zones at max speed (44 u/s) with **0 crashes**, plus sloppy-bot and
  no-input control runs.
* `npm run build` — production Vite build verified; the built `dist/` was
  served and every referenced file (entry bundle, CSS, all runtime textures,
  sprites and UI images) returned HTTP 200.

**Could not be performed here** (no GPU browser available to install): visual
pixel checks, audible audio output, touch-gesture testing on real hardware,
and long-session memory profiling in a browser tab. The pooled,
allocation-free design and the headless soak runs above are the mitigations
for those checks.
